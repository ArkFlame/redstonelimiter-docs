Questions, answered.

Common questions from server administrators, including the settings that are easy to misunderstand.

What does “regions.enabled: true” actually do?

It activates an aggregate activity limit for each 32×32-chunk region. All reached activity within that large area contributes to the region's period count. The base maximum is regions.max-activations (default 96), and preset/TPS multipliers may raise it. This is not the same as a single chunk limit.

I only want to stop big machines that lag one area. What settings should I start with?

Start with blocks and subchunks to target an individual device or compact machine. Inspect stats with /rl and /rl chunk, then adjust chunks if many devices across a chunk add up. Use regions deliberately because a single region covers 1,024 chunks. The first example demonstrates a local-only approach.

Does “max-activations: 5” mean only five uses forever?

No. It means five allowed recorded attempts inside the configured duration-millis activity window, before preset and TPS multipliers. A sixth attempt exceeds the effective threshold when it remains 5. Older activity eventually drops out or the fixed period resets.

What is the difference between duration and sustain?

duration-millis measures how long the plugin counts recent activity. sustain-millis is the temporary block duration after the count goes over the limit. Continued excessive attempts extend the temporary block. Neither is a permanent quarantine.

Does disabling a scope turn all redstone protection off?

No. It stops that particular scope from threshold-blocking, but still records its telemetry. Other enabled scopes, manual quarantine and independent piston push-size checks can still block activity. Disabling a whole world using disabled-worlds is different: it bypasses the plugin's counting/blocking/notification pipeline for that world.

What does setting a max to 0 mean?

Zero means unlimited for that specific scope or material threshold. For example, PISTON: 0 removes the individual-piston activity maximum, but other scopes and max_piston_push can still block piston activity. Oversized piston extensions are cancelled before the automatic-limit whitelist check. This does not mean “always block”.

Why is a piston blocked even though its configured max hasn't been reached?

A wider scope (subchunk, chunk, or region) might have hit its limit, a prior over-limit attempt may still be under sustain, the piston may push more than max_piston_push blocks, or the chunk may be manually quarantined. Check TPS scaling and the preset before comparing raw counts to the base max.

Does the plugin automatically quarantine laggy chunks?

No. Automatic limits temporarily block the offending activity scope. Quarantine is manual only, stays until removed, and overrides whitelist entries.

What is sliding=true vs false?

With true, the count represents the recent rolling duration (using time buckets). With false, counting uses a fixed period that resets when its duration elapses. A previous sustain deadline may continue after the reset.

Why does STRICT allow more activations than my YAML number?

STRICT uses a 1× preset multiplier. The separate TPS multiplier is enabled by default and can reach 2× at or above 19.5 TPS. For example, a base maximum of 3 can become 6. Turn TPS scaling off only if you want fixed effective maxima.

Does RedstoneLimiter limit mobs, entities or hoppers moving items?

Its core purpose is observable redstone/circuit events, not generic entity limiting. The HOPPER material threshold concerns observed redstone-related activity, not every inventory item transfer or a universal hopper-item throughput limit.

How do I get notifications and find a bad machine?

Allow redstonelimiter.notify (or your customized notifications.permission), confirm notifications.enabled: true, and use /rl notifications. View aggregate stats with /rl and the control panel with /rl gui.

Can I change everything in the GUI?

The GUI supports scope limits, per-material maxima, presets, whitelist and quarantine policies. Some advanced settings such as Redis networking and notification cache sizing are documented in config.yml instead.

Is RedstoneLimiter compatible with Folia?

The uploaded plugin descriptor declares folia-supported: true. Actual runtime compatibility should still be validated on the exact server build you operate. The word “region” in this plugin's thresholds is a fixed 32×32-chunk geometric area, not a Folia scheduler region.

I edited config.yml but the changes don't appear. What now?

Check indentation (YAML uses spaces), ensure you changed the appropriate scope and material key, save the file and run /rl reload with permission. Consider the effects of preset/TPS scaling and broader scopes. If your server uses a migrated config, compare with the current defaults.
