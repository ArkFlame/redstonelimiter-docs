CORE SETTINGS

The four limiting scopes

Each of blocks, subchunks, chunks and regions has the same period-related keys. Material-specific maxima are stored under blocks.max-activations.*.

Setting suffixDefaultMeaning
enabledtrueWhen false, this scope does not threshold-block. It still records telemetry. Other enabled scopes can still block.
period.duration-millis5000Count attempts over 5,000 milliseconds (5 seconds). Each scope has its own duration.
period.sustain-millis2000Temporary time to remain blocked after an over-limit attempt; more attempts can extend it.
period.slidingtruetrue counts in a rolling window; false uses fixed periods with resets.
max-activationsScope-specificThe maximum attempts allowed in this scope per period, before multipliers. 0 disables the threshold for this scope.
ScopeEnabledBase maxArea
blockstrueIndividual material thresholds belowOne exact position
subchunkstrue9616×16×16 blocks
chunkstrue102416×16 horizontal footprint
regionstrue9632×32 chunks
Enabling regions does not “protect each block”. It activates an aggregate limit over a very large 512×512-block area. With a base maximum of 96 across all its chunks, you may affect unrelated farms. Individual block and subchunk scopes are more focused. See the four-scope animation →
config.yml
# Partial YAML example. Keep the other sections in your config.
regions:
  enabled: false
  period:
    duration-millis: 5000
    sustain-millis: 2000
    sliding: true
  max-activations: 96
